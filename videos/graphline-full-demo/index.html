This is Graphline, an ANTIINTERNS support agent built for Graph Hacks.
It uses Falkor DB to connect customers, conversations, policies and teams.
We will follow real local interactions, see the agent take action, and
inspect the graph records behind those decisions.
The inbox loads its conversations and record counts from Falkor DB.
This workspace contains only synthetic sample data.
We can search for Maya and open her conversation.
The chat is in the center.
On the right, the application will show the actual decision path and
earlier customer context.
Maya says her delivery is late and the tracking has not changed.
The agent matches words against keyword nodes in the graph.
It follows the selected delivery intent to the approved delivery policy and
the Logistics team.
The reply asks for an order number.
The decision panel explains the path and identifies the reply source as
graph policy.
Now Maya requests a refund.
That matches a different intent.
The connected returns policy requires a person, so the agent creates a
ticket in Falkor DB and links it to the conversation, the intent
and the Returns team.
The ticket count updates from the live graph.
This is a recorded action, not just a generated suggestion.
Ari asks to speak with a human agent.
The graph routes the case to Support and creates a ticket.
An unrecognized invoice question also falls back to human assistance.
This prototype records the handoff and replies with that outcome.
It does not simulate a support employee completing the case.
Next, we create a fresh conversation using the same synthetic customer name.
Graphline links it to the existing customer record.
After a new delivery message, the agent traverses that customer's earlier conversations
and retrieves their messages.
The memory panel shows the actual earlier exchange, including the refund request,
across the conversation boundary.
Reloading the browser keeps the customer conversations and ticket counts.
They are retrieved again from Falkor DB.
The interface is a view over persistent graph records.
It is not keeping the customer history only in browser memory.
This read only presenter view runs Cypher directly against the same demonstration
graph.
The first query follows each intent to its policy and responsible team.
The next query shows the tickets we just created, along with their
assigned teams.
These results are read from Falkor DB while this recording is running.
The memory query follows Maya's customer node to every connected conversation and
message.
The earlier and later messages appear together because the customer relationship connects
them.
The graph summary also shows the real node and relationship counts.
Removing Falkor DB removes the records, routing context, policies and ticket actions
this application depends on.
The source includes optional OpenRouter reply drafting.
Without a configured key, as in this recording, the graph's stored response
is used.
A language model can help phrase an answer, but the graph still
owns intent matching, memory, routing and ticket creation.
This standalone prototype does not connect to WhatsApp or send external messages.
A real channel adapter is future integration work.
The public repository contains the source, graph model, Cypher queries and local
setup instructions.
Start Falkor DB with Docker Compose, then run npm start.
The README discloses Codex assistance and the project's scope.
